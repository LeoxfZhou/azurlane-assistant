碧蓝航线装备仓库（Mac）

历史实现记录：下文保留旧统一助手入口和目录描述。
当前启动器为“启动碧蓝航线助手.command”，个人存档直接位于 user_data/。
最新操作指南见 OTHER_FEATURES.md；存档与交换见 DATA_AND_SYNC.md。

打开方式
双击项目根目录的“启动游戏助手.command”，进入“碧蓝航线 → 装备仓库”。
旧服务需要重新启动后才能使用新增接口。

日常使用
1. 添加仓库装备，选择完整型号（T0/T1/T2/T3 不混并），填写数量。
2. 修改后自动保存在本机。数量设为 0 仅移除本地记录，不操作游戏。
3. 按名称、类型、S/A/B/C/D、普通/特殊栏筛选；点击卡片查看依据和研发用途。
4. 导出库存得到 JSON 文件。导入先预览整份替换的变化，确认后保存并备份旧库存。
5. “参考图鉴”可以查看未持有的装备；“我的库存”只展示已录入的仓库装备。

评级与保护范围
等级是本工具根据攻略整理的判断，不是攻略作者直接发布的 S—D 评分。
普通栏：已核实可常驻获取。特殊栏：联动、账号只能领取一次、当前活动限定。
同一艘船只能装备一件不算账号唯一；高性能舵机等仍归普通栏。
强化与锁定只记录状态，不改变评级。没有数量保留线，没有自动拆解操作。
材料装备保持自身战斗评级，另显示已核实的研发成品及等级。
没有查全的获取渠道独立列入“待核实”，没有足够评级依据的型号列入“待评级”。

当前资料覆盖（2026-10-11 整理）
常规装备图鉴 932 种型号，不含特殊兵装。221 种已按攻略整理评级。
已采用最新攻略：装备一图榜第 119 期，2025-08-28；不是 2026 年最新强度结论。
另保留第 118 期的少量已核对文字判断，而非声称完整评审所有历史版本。
当前没有足够已核实依据的 D 级清单；未上榜、低稀有度均不会自动判 D。
获取渠道和研发路线仍有未覆盖部分。这里只展示已核对的事实，不推断缺失信息。
后续按用户要求更新资料；新一期未提及某装备不会直接抹除旧判断。
日常运行离线，不会自动抓取或覆盖攻略。原图、事实快照和历期判断分开保存。

库存文件约定（供以后 Windows 对接）
UTF-8 JSON，format 固定为 azur-lane-equipment-inventory，schemaVersion 为 1，scope 为 warehouse。
示例：
{
  "format": "azur-lane-equipment-inventory",
  "schemaVersion": 1,
  "scope": "warehouse",
  "entries": [
    {"equipmentId": "维修工具T3", "name": "维修工具T3", "quantity": 4,
     "enhancement": 13, "locked": false, "note": "仓库统计"}
  ]
}
equipmentId 是本图鉴完整型号名称，不能只传不带型号的通称。
quantity 为 1—999999 的整数；enhancement 为 0—13 或 null（未知/未区分）。
同一 equipmentId + enhancement + locked 只允许一条，导出端应先合并数量。
未知型号仍原样保存并列为待评级；不要通过名字相似自动替换型号。
只传仓库成品装备，不包括已装备的装备和设计图。导入的评级字段不生效。
最多 20000 条记录，文件最多 4 MB。版本或范围不符时拒绝，不覆盖现存库存。

保存与恢复
存档位于程序当前用户数据目录下的 azur_lane/equipment_inventory.json。
用户数据根目录沿用现有程序配置；可通过 GAME_GUI_USER_DATA_DIR 为测试隔离。
旧库存保存在同目录的 equipment_backups 中，每次变化保存带时间戳的独立 JSON。
恢复方式：在页面中导入需要恢复的备份，先核对预览再确认。
导入预览期间库存若变化，旧预览会被拒绝，请重新载入并重新导入。
原存档损坏会报错，不会静默重置为空。

资料与空间
data/azur_lane/equipment 存放图鉴、整理评级、事实来源、榜图和图片历史索引。
本次该目录约 3.3 MB；其中只保存本次采用的榜图，不批量保存全部历史图片。
每期只增加文字判断通常是几十至几百 KB；另存完整榜图通常增加几 MB，取决于原图。
库存文件通常几十至几百 KB，备份按实际修改次数累积。
tools/build_equipment_catalog.py 可离线重建已审核参考数据，不改用户库存。
Windows 模拟器识别功能和同步包未包含在本次实现中。
